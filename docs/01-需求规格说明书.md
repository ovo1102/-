## 1. 引言

### 1.1 项目背景与意义

在信息安全领域，文件完整性校验是计算机取证、恶意代码检测、主机文件巡检等工作的基础技术。文件被篡改、植入恶意程序后，其字节内容必然发生变化；为文件计算哈希摘要（“数字指纹”）后，任何一字节的修改都会导致哈希值改变，据此可及时发现篡改行为。

本项目使用 Java 语言实现一个本地文件完整性哈希校验桌面工具，采用面向对象分层设计，将文件扫描、哈希计算、并发调度、报告输出等职责封装为独立模块，并结合 Swing 图形界面、固定线程池并发等技术完成批量校验，是对流程控制、面向对象、异常处理、常用类、IO 流、线程并发、图形编程等课程知识的综合工程化实践。

### 1.2 项目目标

开发一个界面友好、可批量处理、结果可导出、健壮稳定的本地文件哈希校验桌面工具：

1. 支持对单个文件或整个文件夹递归计算 MD5、SHA-256 哈希值；
2. 支持固定线程池批量并发计算，计算期间图形界面不卡顿（不阻塞 EDT）；
3. 校验结果在界面逐条显示，并可导出为本地 UTF-8 文本（txt）报告；
4. 对文件不存在、无权限、IO 错误等异常进行捕获与友好提示，程序不崩溃；
5. 采用界面层 / 业务层 / 数据访问层三层面向对象设计，职责单一、可测试、可扩展。

## 2. 功能需求

### FR-1 文件选择

- 可通过文件选择器单选**一个文件**，或选择**一个文件夹**；
- 界面显示已选中的绝对路径；
- 未选择任何路径时点击“开始校验”，以弹窗给出提示，不执行计算。

### FR-2 哈希计算

- 支持 MD5、SHA-256 两种算法，以下拉框选择；
- 对单个文件输出**小写十六进制**哈希字符串；
- MD5 为 32 位、SHA-256 为 64 位；
- 采用 4096 字节缓冲区分块读取，大文件不全量载入内存。

### FR-3 批量处理

- 对文件夹递归得到的全部文件，使用固定大小线程池（4 线程）并发计算；
- 计算过程中界面保持可响应（计算任务不在 EDT 执行）；
- 实时显示进度（已完成数 / 总数）；
- 计算期间禁止重复提交（按钮禁用）。

### FR-4 结果展示

- 界面结果区逐条显示“序号、文件绝对路径、算法、哈希值/错误信息”；
- 失败记录显示失败原因而非哈希；
- 支持一键清空结果区与本次结果缓存。

### FR-5 报告导出

- 将本次校验结果写入用户指定的本地 txt 文件（UTF-8 编码）；
- 报告包含：报告标题、生成时间、算法名、每条记录（含失败记录的错误原因）、统计信息（成功/失败计数）；
- 无结果时点击导出给出提示。

### FR-6 异常处理

- 文件不存在、目标是目录而非文件、无读取权限、IO 错误、非法算法名等情况均被捕获；
- 工具方法按 Javadoc 声明抛出受检/非受检异常；
- 批量场景下单文件失败不影响其他文件执行，失败项以失败状态记录；
- 界面以弹窗或结果区错误行友好提示，任何异常都不导致程序崩溃。

### FR-7 递归扫描

- 正确区分文件与目录，递归遍历所有子目录中的全部文件；
- 对无权限目录（`listFiles()` 返回 `null`）做空值保护并跳过，不抛出空指针异常；
- 单文件输入返回仅含该文件的列表。

## 4. 用例描述

### 4.1 用例总表

| 用例编号 | 用例名称 | 参与者 | 前置条件 |
| --- | --- | --- | --- |
| UC-1 | 选择文件 | 用户 | 程序已启动 |
| UC-2 | 选择文件夹 | 用户 | 程序已启动 |
| UC-3 | 单文件哈希校验 | 用户 | 已选中一个文件 |
| UC-4 | 文件夹批量校验 | 用户 | 已选中一个文件夹 |
| UC-5 | 查看进度与结果 | 用户 | 校验任务执行中或已完成 |
| UC-6 | 清空结果 | 用户 | 结果区存在内容 |
| UC-7 | 导出 txt 报告 | 用户 | 本次校验存在结果 |

### 4.2 主要用例流程（UC-4 文件夹批量校验）

1. 用户点击“选择文件夹”，在文件选择器中选定目录；
2. 路径行显示该目录绝对路径；
3. 用户在算法下拉框选择 MD5 或 SHA-256；
4. 用户点击“开始校验”，系统禁用操作按钮，后台线程递归扫描目录得到文件列表；
5. 进度条置总数，业务层用 4 线程池并发计算每个文件的哈希；
6. 每完成一个文件，回调经 `SwingUtilities.invokeLater` 在 EDT 追加结果行并更新进度；
7. 全部完成后状态栏提示“校验完成”，按钮恢复可用，结果缓存供导出。

**异常流：**

- 4a. 未选择路径：弹窗“请先选择文件或文件夹”，用例终止；
- 6a. 某文件无权限/已删除/IO 失败：该条记录标记失败并写明原因，其余文件继续；
- 扫描到无权限子目录：跳过该目录，继续遍历其余分支。

### 4.3 关键异常流（UC-7 导出报告）

- 7a. 尚无校验结果：弹窗提示“暂无可导出的结果”；
- 7b. 保存路径不可写/为目录：捕获 IOException，弹窗提示失败原因，程序继续运行。

## 5. 数据需求

| 数据 | 形式 | 说明 |
| --- | --- | --- |
| 文件路径 | `java.io.File` / 绝对路径字符串 | 用户选择的文件或目录 |
| 算法名 | 字符串 `MD5` / `SHA-256` | 直接透传给 `MessageDigest.getInstance` |
| 哈希值 | 小写十六进制字符串 | MD5 32 位 / SHA-256 64 位 |
| 单条结果 | `FileHashResult`（不可变模型） | 路径、算法、哈希值、成功标志、错误信息 |
| 结果集合 | `List<FileHashResult>` | 按扫描/输入顺序排列，供展示与导出 |
| 报告文件 | 本地 txt（UTF-8） | 标题、时间、算法、明细、统计 |

系统不使用数据库，不产生任何网络数据。

## 6. 约束条件

- **技术约束**：Java（JDK 8 字节码目标，JDK 21 实际构建）、Swing、`MessageDigest`、Maven；运行时零第三方依赖；测试用 JUnit 5。
- **命名约束**：文件扫描类沿用策划书拼写 `FileScaner`（非标准拼写 Scanner），以与策划书及验收材料保持一致，设计文档中对此明确注明。
- **进度约束**：需求 1d / 概要 1d / 详细 1d / 编码 3d / 测试 1d / 文档 2d。
- **依赖约束**：首次构建需可访问 Maven 中央仓库以下载 JUnit 5 与构建插件。

## 7. 可行性分析

### 7.1 技术可行性

所需技术全部来自课程知识体系：面向对象、异常处理、常用类、IO 流、线程并发、Swing 图形编程；哈希算法由 JDK 内置 `MessageDigest` 提供，无需第三方库；Maven 保证构建可重复。技术实现简单可靠，可行。

### 7.2 经济可行性

JDK、Maven、JUnit 均为免费软件，开发与运行无需额外硬件或商业软件采购，经济上可行。

### 7.3 合规性分析

仅对用户主动选择的**本地**文件执行只读哈希计算，不扫描公网或他人系统，不进行任何网络通信、数据采集或上传，无违法违规风险，合规可行。
