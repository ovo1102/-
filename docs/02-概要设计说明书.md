## 1. 引言

本文档在《需求规格说明书》的基础上描述系统总体架构、模块划分、类职责、类间关系、并发模型与关键设计决策，作为详细设计与编码的依据。

## 2. 系统架构设计

系统采用“界面层 — 业务层 — 数据访问层”三层结构，并辅以独立的模型包承载跨层数据。各层职责单一、单向依赖，不得反向调用。

```
┌───────────────────────────────────────────────────────────────┐
│  界面层 ui  （com.hashcheck.ui）                               │
│  HashCheckGUI：Swing 窗口、事件监听、EDT 渲染、弹窗提示        │
└───────────────▲───────────────────────────────▲───────────────┘
                │ 调用（事件触发，仅做编排）      │ 调用（导出）
┌───────────────┴───────────────────────────────┴───────────────┐
│  业务层 service  （com.hashcheck.service）                    │
│  FileScaner：文件/目录递归扫描                                │
│  HashUtil：MD5 / SHA-256 分块哈希计算（纯静态工具）           │
│  HashCheckService：固定线程池并发编排、异常收口、进度回调     │
└───────────────▲───────────────────────────────┬───────────────┘
                │ 使用                          │ 产出/消费
┌───────────────┴───────────────────────────────▼───────────────┐
│  模型 model  （com.hashcheck.model）                          │
│  FileHashResult：不可变结果对象（路径/算法/哈希/状态/原因）   │
└───────────────────────────────────────────────────────────────┘
                │ 业务层将结果集合交给 IO 层落盘
┌───────────────▼───────────────────────────────────────────────┐
│  数据访问层 io  （com.hashcheck.io）                          │
│  ReportWriter：UTF-8 txt 报告写入（两种重载）                │
└───────────────────────────────────────────────────────────────┘
```

**依赖方向约束：**

- `ui` 依赖 `service`、`io`、`model`，但业务层与 IO 层不感知 Swing 的存在；
- `service` 依赖 `model`；`io` 依赖 `model`；`model` 不依赖任何其他包；
- 所有跨层数据以 JDK 标准类型（`File`、`List`、`String`）或 `FileHashResult` 传递。

## 3. 模块划分与类职责表

| 类名 | 所在包/层 | 类型 | 职责 |
| --- | --- | --- | --- |
| `HashCheckGUI` | `ui` / 界面层 | Swing JFrame | 窗口与控件初始化、按钮事件监听、后台任务触发、EDT 结果渲染、弹窗提示；程序 main 入口 |
| `HashUtil` | `service` / 业务层 | 静态工具类（final） | 基于 `MessageDigest` + 4096 字节分块读取计算单文件哈希，输出小写十六进制串 |
| `FileScaner` | `service` / 业务层 | 静态工具类（final） | 区分文件/目录，递归扫描目录树，`listFiles()` 为 null 时跳过 |
| `HashCheckService` | `service` / 业务层 | 普通类（可实例化） | 4 线程固定池并发调度、单任务异常收口为失败结果、进度回调、按输入顺序返回、池的创建与关闭 |
| `FileHashResult` | `model` / 模型 | 不可变对象 | 承载单文件校验结论：路径、算法、哈希值、成功标志、错误信息；静态工厂构造 |
| `ReportWriter` | `io` / 数据访问层 | 静态工具类（final） | 将 `Map` 或 `List<FileHashResult>` 以 UTF-8 写入结构化 txt 报告 |

> **命名说明（遵循策划书）：** 文件扫描类保留策划书原拼写 `FileScaner`（标准英文应为 Scanner），以保证与策划书、验收材料的一致性。

## 4. 类关系说明

```
HashCheckGUI ──uses──> FileScaner.scanFiles()           // 获取待校验文件列表
             ──uses──> HashCheckService.checkAll()      // 提交并发批量校验
             ──uses──> ReportWriter.saveReport()        // 导出 txt 报告
             ──renders─> List<FileHashResult>           // 在结果区逐条渲染

HashCheckService ──uses──> HashUtil.getFileHash()       // 工作线程内逐文件计算
                ──produces─> FileHashResult             // 成功/失败两种结果
                ──notifies──> ProgressCallback          // 每完成一个文件回调进度

ReportWriter ──consumes──> List<FileHashResult> / Map<String,String>
```

三个工具类（`HashUtil`、`FileScaner`、`ReportWriter`）均为 final 类、私有构造、纯静态方法，无状态、线程安全；`HashCheckService` 为可实例化类，线程数可经构造方法注入以便测试；`FileHashResult` 一经创建不可修改，可安全地在线程间传递。

### 4.1 相对策划书的工程化细化（设计决策）

策划书第 4 章规划了 `HashCheckGUI` / `HashUtil` / `FileScaner` / `ReportWriter` 四个核心类。本实现在不改变策划书意图的前提下做两处细化：

1. **新增 `model.FileHashResult` 与 `service.HashCheckService`**：策划书 4.1 要求业务逻辑与界面解耦，而“固定线程池并发调度、异常收口、进度回调”本质属于业务逻辑。若留在 GUI 中，将导致界面类臃肿且无法对并发行为做自动化测试。故将其下沉为业务层服务类，并用不可变结果模型完整表达失败项（策划书的 `Map<String,String>` 无法表达失败原因）。
2. **`ReportWriter` 在策划书签名上增加重载**：保留策划书规定的 `saveReport(File, Map<String,String>)`，另增加 `saveReport(File, List<FileHashResult>, String)`，用于完整导出算法名、失败原因与成功/失败统计。

## 5. 并发与 EDT 设计

```
EDT（AWT-EventQueue-0）                 工作线程
─────────────────────────               ─────────────────────────────
点击“开始校验”
  校验已选路径
  禁用按钮、进度条归零
  new Thread("hashcheck-batch") ──────►  FileScaner.scanFiles()（递归扫描）
                                          设置进度条总数（invokeLater 回切）
                                          ExecutorService fixedPool(4)
                                            ├─ worker-1: HashUtil 计算
                                            ├─ worker-2: HashUtil 计算
                                            ├─ worker-3: HashUtil 计算
                                            └─ worker-4: HashUtil 计算
                                            每完成一个：callback(completed,total,result)
  ◄──── SwingUtilities.invokeLater ──────   追加结果行、setProgress(completed)
  ◄──── SwingUtilities.invokeLater ────── 全部完成：恢复按钮、状态栏提示、缓存结果
                                          pool.shutdown()（已确保关闭）
```

设计要点：

1. **任何哈希计算都不在 EDT 执行**：监听方法只做禁用按钮与启动后台线程；
2. **线程池生命周期清晰**：每次批量任务内部创建 `newFixedThreadPool(threadCount)`，任务全部收尾后 `shutdown()` + `awaitTermination`，不跨批次复用、不泄漏；
3. **空列表不创建线程池**：无文件时直接返回空结果；
4. **结果有序**：每个任务带输入下标写入结果数组占位，最终按输入顺序返回，与完成先后无关；
5. **回调在工作线程触发**：`ProgressCallback` 契约中明确由 UI 自行 `invokeLater` 切回 EDT，业务层不导入任何 Swing 类；
6. **异常收口**：工作任务 `catch (Exception)` 全部转换为失败 `FileHashResult`，批量整体不抛出业务异常（除中断异常向上声明外）。

## 6. 关键设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 文件读取 | 4096 字节缓冲区 + `FileInputStream` 分块 `digest.update` | 大文件不全量入内存，内存占用恒定约 4KB/任务 |
| 资源管理 | try-with-resources | 流自动关闭，杜绝异常路径资源泄漏 |
| 并发模型 | `Executors.newFixedThreadPool(4)`（可注入线程数） | 与策划书一致；控制并发度，便于测试观测多线程 |
| 十六进制编码 | 手写 `0xff & b` + `Integer.toHexString` 补零 | 零第三方依赖，兼容 JDK 8；JDK 17 的 HexFormat 不可用于 release 8 |
| 结果模型 | 不可变对象 + 静态工厂 `success/failure` | 线程安全；成功/失败语义显式，避免 null 约定 |
| 异常策略 | 工具方法抛受检异常；服务层收口为失败结果 | 底层保持错误信息完整，上层保证批量不中断 |
| 报告编码 | UTF-8（`StandardCharsets.UTF_8`） | 跨平台、中文路径与错误信息不乱码 |
| 界面构建 | 全部控件在 EDT 初始化（`SwingUtilities.invokeLater`） | 符合 Swing 单线程模型 |
| 构建目标 | `--release 8` | 字节码兼容 JRE 8+，实际由 JDK 21 构建 |

## 7. 异常流设计

| 场景 | 检测点 | 行为 |
| --- | --- | --- |
| 文件/目录不存在 | `File.exists()` | 工具方法抛 `FileNotFoundException`；服务层记录失败结果；GUI 弹窗 |
| 以目录作为计算目标 | `File.isDirectory()` | HashUtil 抛 `IOException`；批量记录失败 |
| 无权限子目录 | `listFiles()` 返回 null | FileScaner 跳过该目录继续扫描 |
| 无读取权限/IO 错误 | `FileInputStream` 构造/读取抛出 | 单文件失败，其余文件继续 |
| 非法算法名 | `MessageDigest.getInstance` | 抛 `NoSuchAlgorithmException`；GUI 算法来源固定为下拉框，正常路径不可达 |
| null 入参 | `Objects.requireNonNull` / 显式判断 | 抛 `NullPointerException` / `IllegalArgumentException`（快速失败） |
| 导出目标为目录 | `File.isDirectory()` | ReportWriter 抛 `IOException`，GUI 弹窗提示 |

## 8. 部署与构建视图

- `mvn clean test`：编译 + 运行全部 JUnit 5 用例 + 生成 surefire 与 JaCoCo 报告；
- `mvn package`：生成带 `Main-Class: com.hashcheck.ui.HashCheckGUI` 清单的可执行 jar；
- 交付启动脚本：`运行-哈希校验工具.bat`（Windows，javaw 启动无控制台窗口）、`run.sh`（Linux/macOS）。
