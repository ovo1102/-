## 2. model.FileHashResult（结果模型）

不可变值对象，描述单个文件的一次校验结论。类声明为 `final`，字段全部 `private final`，仅提供 getter 与静态工厂，不提供 setter。

### 2.1 属性

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `filePath` | `String` | 被校验文件的绝对路径（构造时取 `File.getAbsolutePath()`） |
| `algorithm` | `String` | 算法名（`MD5` / `SHA-256`） |
| `hash` | `String` | 成功时的小写十六进制哈希；失败时为 `null` |
| `success` | `boolean` | 成功标志；`true` 成功、`false` 失败 |
| `errorMessage` | `String` | 失败原因；成功时为 `null` |

### 2.2 方法

| 签名 | 说明 |
| --- | --- |
| `public static FileHashResult success(File file, String algorithm, String hash)` | 成功工厂：校验 file/algorithm/hash 非空，记录路径与哈希，success=true |
| `public static FileHashResult failure(File file, String algorithm, String errorMessage)` | 失败工厂：file 与 errorMessage 非空，hash=null，success=false |
| `String getFilePath()` | 返回文件绝对路径 |
| `String getAlgorithm()` | 返回算法名 |
| `String getHash()` | 返回哈希值（失败可能为 null） |
| `boolean isSuccess()` | 返回是否成功 |
| `String getErrorMessage()` | 返回失败原因（成功可能为 null） |
| `String toString()` | 返回便于日志阅读的中文摘要，不在 GUI 渲染路径使用 |

**异常约定：** 静态工厂对必要参数为 null 时抛 `NullPointerException`（`Objects.requireNonNull`，携带中文字段名）。

## 3. service.HashUtil（哈希计算工具类）

`public final class HashUtil`，私有构造方法，不可实例化、不可继承；无状态，线程安全。

### 3.1 常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `BUFFER_SIZE` | `4096` | 分块读取缓冲区字节数（策划书规定） |

### 3.2 方法

```java
public static String getFileHash(File file, String algorithm)
        throws IOException, NoSuchAlgorithmException
```

| 项目 | 说明 |
| --- | --- |
| 参数 `file` | 目标文件，不能为 null，必须存在且不是目录 |
| 参数 `algorithm` | 算法名，不能为 null；合法值 `MD5`、`SHA-256` |
| 返回值 | 小写十六进制哈希字符串（MD5 32 位 / SHA-256 64 位） |
| `NullPointerException` | `file` 或 `algorithm` 为 null |
| `FileNotFoundException` | 文件不存在（`IOException` 子类） |
| `IOException` | 目标是目录、无读取权限或读取过程发生 IO 错误 |
| `NoSuchAlgorithmException` | JDK 不支持该算法名 |

### 3.3 实现要点

1. `Objects.requireNonNull` 校验两个参数；
2. `!file.exists()` → 抛 `FileNotFoundException`；`file.isDirectory()` → 抛 `IOException`，异常消息携带路径；
3. `MessageDigest.getInstance(algorithm)` 创建摘要器；
4. try-with-resources 管理 `FileInputStream`；循环 `read(buffer)` → `digest.update(buffer, 0, len)` 直到 -1；
5. `digest.digest()` 得到定长字节数组；逐字节 `0xff & b` 转无符号整数，`Integer.toHexString` 后对单位数前补 `0`，拼接为小写串返回；
6. 方法为纯函数式计算，不在内部做任何 UI、网络、数据库操作。

## 4. service.FileScaner（文件扫描类）

`public final class FileScaner`，私有构造。类名沿用策划书拼写（非 Scanner）。

### 4.1 方法

```java
public static List<File> scanFiles(File root) throws IOException
```

| 项目 | 说明 |
| --- | --- |
| 参数 `root` | 文件或目录，不能为 null，必须存在 |
| 返回值 | `ArrayList<File>`：root 为文件返回单元素列表；为目录返回递归收集到的全部普通文件（不含目录本身） |
| `IllegalArgumentException` | `root` 为 null |
| `FileNotFoundException` | 路径不存在（`IOException` 子类） |

### 4.2 实现要点

1. null 校验与存在性校验见上表；
2. root 是普通文件 → 直接加入新 `ArrayList` 返回；
3. root 是目录 → 调用私有递归方法 `scanDirectory(File dir, List<File> result)`：
   - `File[] children = dir.listFiles()`；
   - **children 为 null（无权限或 IO 错误）时直接 return 跳过该分支**，实现空值保护；
   - 遍历 children：`isFile()` 收集；`isDirectory()` 递归；两者皆非（特殊文件）跳过；
4. 不做去重以外的排序保证，调用方对顺序不做依赖；同一路径不会被重复加入；
5. 空目录返回空列表（非 null）。

## 5. service.HashCheckService（并发批量校验服务）

`public class HashCheckService`，可实例化；线程数可构造注入（默认 4）。不依赖 Swing。

### 5.1 嵌套接口

```java
@FunctionalInterface
public interface ProgressCallback {
    /** 每完成一个文件（成功或失败）回调一次；在工作线程触发，UI 需自行切回 EDT */
    void onProgress(int completed, int total, FileHashResult latest);
}
```

### 5.2 常量与属性

| 成员 | 说明 |
| --- | --- |
| `DEFAULT_THREAD_COUNT = 4` | 默认固定线程池大小（策划书规定） |
| `private final int threadCount` | 本实例使用的池大小，构造后不变 |

### 5.3 方法

| 签名 | 说明 |
| --- | --- |
| `public HashCheckService()` | 默认构造，等价 `HashCheckService(4)` |
| `public HashCheckService(int threadCount)` | 注入线程数；小于 1 抛 `IllegalArgumentException` |
| `public FileHashResult checkOne(File file, String algorithm)` | 单文件便捷校验：内部调用 `HashUtil.getFileHash`，捕获**所有**异常转换为 `FileHashResult.failure`，不向调用方抛业务异常 |
| `public List<FileHashResult> checkAll(List<File> files, String algorithm) throws InterruptedException` | 无回调重载，等价于传入 `null` 回调 |
| `public List<FileHashResult> checkAll(List<File> files, String algorithm, ProgressCallback callback) throws InterruptedException` | 核心批量方法，见 5.4 |

### 5.4 checkAll 实现要点

1. 入参校验：`files`/`algorithm` 为 null 抛 `IllegalArgumentException`；
2. **空列表短路**：直接返回空 `ArrayList`，不创建任何线程池（保证无线程泄漏）；
3. 用 `Executors.newFixedThreadPool(threadCount)` 创建池；`results = new FileHashResult[files.size()]` 占位数组；`AtomicInteger completed` 计数；
4. 遍历文件按下标 `i` 提交任务：
   - 任务体调用 `checkOne(file, algorithm)`（file 为 null 时得到失败结果）；
   - 写入 `results[i]`；
   - `int done = completed.incrementAndGet()`；若非 null 回调，调用 `callback.onProgress(done, total, result)`（回调异常由调用方负责，本服务不吞回调异常以外的主流程——实现中回调放在任务内，回调抛出会导致该任务异常，故回调调用做安全防护：回调本身异常不影响计数与结果）；
5. 提交后 `shutdown()` 并 `awaitTermination(Long.MAX_VALUE, NANOSECONDS)` 等待全部任务；若中断则恢复中断标志并抛 `InterruptedException`；
6. 返回 `Arrays.asList(results)` 包装后的新 `ArrayList`：**顺序严格等于输入顺序**；
7. 使用 try/finally 确保任何退出路径都执行 `shutdown()`。

### 5.5 异常收口矩阵

| 任务内情况 | 结果 |
| --- | --- |
| 正常计算 | `success`，携带哈希 |
| 文件不存在/目录/无权限/IO 错误 | `failure`，errorMessage 形如 `FileNotFoundException: 文件不存在: ...` |
| 非法算法 | `failure`，原因为 `NoSuchAlgorithmException: ...` |
| 列表元素为 null | `failure`，原因“文件参数为 null” |

## 6. io.ReportWriter（报告导出类）

`public final class ReportWriter`，私有构造。全部使用 UTF-8 输出。

### 6.1 方法

```java
public static void saveReport(File saveFile, Map<String,String> resultMap) throws IOException
public static void saveReport(File saveFile, List<FileHashResult> results, String algorithm) throws IOException
```

| 项目 | 说明 |
| --- | --- |
| 参数 `saveFile` | 目标文件；为 null 抛 `IllegalArgumentException`；已存在且是目录抛 `IOException` |
| 参数 `resultMap` | 策划书签名：文件路径 → 哈希值映射；为 null 抛 `IllegalArgumentException` |
| 参数 `results` | 结果集合；为 null 抛 `IllegalArgumentException`；元素可为成功或失败 |
| 参数 `algorithm` | 算法名；为 null 抛 `IllegalArgumentException`（Map 重载无算法上下文，报告头写“未知/混合”） |
| 返回 | 无；文件已存在则覆盖写 |

### 6.2 报告格式（List 重载）

```
本地文件完整性哈希校验报告
========================================
生成时间：2026-10-03 14:22:18
哈希算法：MD5
----------------------------------------
[1] 文件路径：D:\demo\a.txt
    哈希值：900150983cd24fb0d6963f7d28e17f72
    状态：成功
[2] 文件路径：D:\demo\locked.bin
    状态：失败
    错误原因：FileNotFoundException: ...
----------------------------------------
统计信息：成功: 1 失败: 1 总计: 2
========================================
```

- 时间取写入瞬间 `LocalDateTime.now()`，格式 `yyyy-MM-dd HH:mm:ss`；
- 明细按列表顺序编号；成功写哈希，失败写错误原因；
- 统计行严格包含 `成功: N 失败: M` 字样，便于自动化断言与人工核对。

### 6.3 Map 重载格式

报告头三行（标题/分隔/时间/算法“未知/混合”）一致；正文逐条写 `文件路径：<key>` + `哈希值：<value>`；末尾写 `记录条数：N`。

### 6.4 实现要点

1. 显式参数校验（null/目录）见异常表；
2. 以 `new OutputStreamWriter(new FileOutputStream(saveFile), StandardCharsets.UTF_8)` 套 `BufferedWriter`，try-with-resources 关闭；
3. `write` + 换行统一 `newLine()`，避免平台换行差异；
4. 纯静态、无状态、无线程。

### 7.3 批量校验时序（onStartCheck）

1. **EDT**：selectedFile 为 null → 信息弹窗“请先选择文件或文件夹”后返回；
2. **EDT**：清空结果区与旧结果，`setControlsEnabled(false)`，进度条归零、状态“校验中…”；
3. 启动后台线程 `hashcheck-batch`：
   1. 调用 `FileScaner.scanFiles(selectedFile)`；扫描异常 → invokeLater 弹窗并恢复按钮，结束；
   2. 文件数为 0 → invokeLater 状态“所选文件夹不包含任何文件”并恢复按钮，结束；
   3. invokeLater 设置进度条最大值 total；
   4. 调用 `service.checkAll(files, algorithm, (done, total, result) -> SwingUtilities.invokeLater(...))`；
   5. 回调内在 EDT 执行 `appendResultLine(done, result)`、`progressBar.setValue(done)`；
   6. 正常返回后 invokeLater：缓存 lastResults、状态“校验完成：成功 X 个，失败 Y 个”、恢复按钮；
   7. `catch (InterruptedException)`：恢复中断标志；`catch (Exception)` 兜底弹窗；finally 中确保按钮恢复。
4. 监听器方法立即返回，EDT 全程不被计算占用。

### 7.4 界面文本

全部中文：窗口标题“本地文件完整性哈希校验工具”；按钮“选择文件(S).../选择文件夹(D).../开始校验/导出报告/清空”；结果区表头行“序号 | 文件路径 | 算法 | 哈希值/错误信息”；算法占位“MD5 / SHA-256”。

## 8. 端到端时序总览

```
用户 → GUI(EDT)：选择文件/目录          → JFileChooser → selectedFile
用户 → GUI(EDT)：开始校验
   GUI(EDT) → 后台线程：FileScaner.scanFiles
   后台线程 → HashCheckService.checkAll（fixedPool=4）
       worker ×N → HashUtil.getFileHash（MessageDigest/4096B 分块）
       worker → FileHashResult(success/failure) → ProgressCallback
   callback → SwingUtilities.invokeLater → GUI(EDT)：追加行+进度
   全部完成 → GUI(EDT)：状态栏/按钮恢复/缓存结果
用户 → GUI(EDT)：导出报告 → JFileChooser → ReportWriter.saveReport（UTF-8 txt）
```

## 9. 测试钩子设计

- 业务/IO 层全部为可直接调用的纯 Java API，使用 JUnit 5 + `@TempDir` 自动化验证；
- `HashCheckService(int threadCount)` 构造注入便于并发用例观测；
- GUI 不引入第三方 UI 测试库，以“启动冒烟 + 代码走查（EDT 规则、监听器齐备）”为验证手段。
